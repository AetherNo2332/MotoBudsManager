# APK 佩戴贴合度检测逆向说明

本文记录 Moto Buds APK 中佩戴贴合度检测（Fit Test）的功能入口、前置条件、协议命令、固件通知、结果解释和 UI 状态机，供 Moto Buds Manager 二次开发与设备适配使用。

除非另有说明，本文结论来自 APK 静态逆向。协议命令已经在 `XT2443-1` 上验证可以启动和停止测试，但不同固件返回的全部结果值仍应通过脱敏实机日志继续验证。

## 核心结论

贴合度判断算法运行在耳机固件中。APK 不使用手机麦克风，不在 Android 端录音或进行频谱、密封度计算，也不通过网络请求获得结果。APK 的职责是：

1. 检查左右耳是否都处于佩戴状态；
2. 向耳机发送开始或停止检测命令；
3. 等待固件主动返回左右耳结果；
4. 将两个结果值映射成通过、左耳失败、右耳失败或双耳失败；
5. 更新按钮、文字和左右耳状态图。

固件内部可能使用扬声器、反馈麦克风或声学泄漏测量，但 APK 只接收最终结果，无法从该 APK 确定固件内部的信号处理算法。

```mermaid
flowchart LR
    A[用户点击开始测试] --> B{左右耳均已佩戴}
    B -- 否 --> C[显示插入两只耳机提示]
    B -- 是 --> D[发送 0x0400 / 01]
    D --> E[耳机固件执行检测]
    E --> F[固件通知 0x0401 / 左结果 / 右结果]
    F --> G[APK 解析结果]
    G --> H[更新左右耳状态图及结果文字]
```

## 前置佩戴检查

APK 从固件维护的 In-Ear 状态中读取左右耳字段：

```text
leftInEar  == 1
rightInEar == 1
canStart   = leftInEar && rightInEar
```

只有左右耳字段同时等于 `1` 才允许开始。任意一侧不满足时，APK 不发送开始命令，而是弹出“无法检测耳机/请插入两只耳机”提示。

这项检查使用的是耳机固件返回的佩戴传感器状态，不是 Android 自行判断。对应静态证据为 `BudsDetailedInfoViewModel` 中对 `oVar.f16928m == 1 && oVar.f16929n == 1` 的判断。

## 控制命令

配置索引 `3` 在协议映射中对应 Opcode `1024`，即 `0x0400`，名称为 `set fit state`。

### 开始测试

```text
Opcode:  0x0400
Payload: 01
Meaning: set fit state = start
```

### 停止测试

```text
Opcode:  0x0400
Payload: 00
Meaning: set fit state = stop
```

静态调用链：

```text
FitTestFragment.start_test
  -> BudsDetailedInfoViewModel.L()
  -> U.B(configType = 3, value = 1)
  -> BudsProxy.v(3, 1)
  -> PduParser.e(3, false) = 0x0400
  -> send payload [01]
```

停止命令走相同路径，仅将值改为 `0`。完整传输帧还包含 PDU 类型、结果、Payload 长度、动态序列号以及 SPP 外层帧/CRC；不能把这里的 Opcode 和 Payload 直接当作完整 RFCOMM 写入数据。

APK 在发送开始命令后还异步记录一次 `FIT_TEST` 统计事件。该统计调用不参与检测算法，也不影响固件结果。

## 固件结果通知

协议表将 Opcode `1025`（`0x0401`）命名为 `fit status changed`。这是耳机固件主动发出的状态通知：

```text
Opcode:  0x0401
Payload: [leftResult, rightResult]
```

通知解析器按一字节字段读取：

```text
payload[0] -> 左耳结果
payload[1] -> 右耳结果
```

APK 对每个字段只检查是否等于 `1`：

```text
leftPassed  = payload[0] == 1
rightPassed = payload[1] == 1
```

因此已知结果组合为：

| Payload | 左耳 | 右耳 | APK 展示 |
| --- | --- | --- | --- |
| `01 01` | 通过 | 通过 | 两只耳机均贴合良好 |
| `00 01` | 失败 | 通过 | 调整左耳或更换耳塞尺寸 |
| `01 00` | 通过 | 失败 | 调整右耳或更换耳塞尺寸 |
| `00 00` | 失败 | 失败 | 调整两只耳机或更换耳塞尺寸 |

严格语义是“`1` 表示通过，任何非 `1` 值按失败处理”。适配未知固件时必须保留原始字节；在没有实机证据前，不应断言 `2`、`0xFF` 等未知值与普通失败完全等价。

## APK 内部状态机

APK 为左右耳分别维护一个 UI 状态整数：

| 状态 | 含义 | UI 资源 |
| --- | --- | --- |
| `1` | 初始/等待 | 普通耳机底图 |
| `2` | 通过 | Active 状态底图 |
| `3` | 失败 | Error 状态底图 |

运行状态另由布尔值维护：

- 开始前：左右状态重置为 `1`；
- 发送开始命令：运行状态设为 `true`；
- 运行中：开始按钮禁用，文字变为“测试中…”；
- 收到 `0x0401`：保存结果、运行状态设为 `false`；
- 通过：对应耳机状态设为 `2`；
- 失败：对应耳机状态设为 `3`；
- 完成后：隐藏开始按钮，显示“重试”和“完成”。

失败耳朵还被编码为：

| 值 | 含义 |
| --- | --- |
| `1` | 左耳失败 |
| `2` | 右耳失败 |
| `3` | 双耳失败 |

## 中断及异常处理

### 测试期间离耳

如果运行过程中 In-Ear 通知显示任意耳机离耳，APK 会：

1. 发送 `0x0400 / 00`；
2. 将运行状态设为 `false`；
3. 将结果设为双耳失败；
4. 弹出“无法检测耳机/请插入两只耳机”提示。

即使只有一侧离耳，该异常分支也统一标记为双耳失败，而不是保留另一侧可能已经产生的结果。

### 主耳切换

测试期间收到主耳切换事件时，APK 会终止当前 UI 流程并标记双耳失败。该分支未直接调用 `0x0400 / 00`，可能依赖连接或固件状态重置。桌面端实现不应照搬这一不确定行为，建议显式发送停止命令并清理本地状态。

### 页面退出和断连

贴合度测试属于瞬时操作。二次开发应在以下情况尽力发送停止命令：

- 用户主动停止；
- 页面退出且测试仍在运行；
- 任意一侧离耳；
- 设备开始断连但传输仍可写；
- 应用关闭或切换设备。

若连接已经断开，则只清理本地运行状态，不能伪造“停止成功”。

## APK 与固件的职责边界

| 能力 | APK | 耳机固件 |
| --- | --- | --- |
| 检查左右耳佩戴状态 | 读取并组合状态 | 产生传感器状态 |
| 启动/停止检测 | 发送 `0x0400` | 执行命令 |
| 声学检测 | 不执行 | 执行 |
| 判定贴合度 | 不计算 | 生成左右耳结果 |
| 结果显示 | 解析 `0x0401` 并更新 UI | 主动发送通知 |

APK 流程中没有发现 `AudioRecord`、手机麦克风采集、本地频谱分析或网络检测接口。因此应用侧不应尝试根据音量、电量或普通佩戴状态自行推导贴合度结果。

## Moto Buds Manager 当前实现

当前项目已经实现：

- `MotoBudsClient.SetFitTestAsync(true)` 发送 `0x0400 / 01`；
- `MotoBudsClient.SetFitTestAsync(false)` 发送 `0x0400 / 00`；
- 将贴合度测试作为瞬时操作，在清理会话时尝试停止；
- 按型号白名单限制功能入口。

当前尚未实现：

- `0x0401` 主动通知解析；
- 左右耳独立结果模型；
- 通过、左失败、右失败、双失败 UI；
- 测试期间离耳自动停止；
- 未知结果字节的诊断记录。

因此现有界面只能确认开始/停止命令是否发送成功，不能显示真正的固件检测结果。

## 建议的数据模型

核心层可以使用以下等价模型，名称仅供实现参考：

```csharp
public enum FitTestEarStatus
{
    Unknown,
    Passed,
    Failed,
}

public sealed record FitTestResult(
    byte RawLeft,
    byte RawRight,
    FitTestEarStatus Left,
    FitTestEarStatus Right);
```

解析时应先验证 Payload 至少包含两个字节，同时保存 `RawLeft` 和 `RawRight`。已知值 `1` 映射为 `Passed`；值 `0` 可映射为 `Failed`；其他值建议先保留为 `Unknown`，由 UI 显示“无法识别结果”，并写入脱敏诊断日志。

## 测试建议

自动化测试至少应覆盖：

1. `0x0400 / 01` 与 `0x0400 / 00` 的精确编码；
2. `0x0401` 的四个已知结果组合；
3. 少于两个字节的异常 Payload；
4. 未知结果值不被错误解释为通过；
5. 测试期间离耳会发送停止命令；
6. 页面退出、断连和会话切换会清理运行状态；
7. 未列入型号白名单的设备无法自动启动测试。

硬件测试必须由用户确认耳机已佩戴，并在安全音量环境中执行。不要通过枚举未知 Opcode 或随机 Payload 探测贴合度功能。
